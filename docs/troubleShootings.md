# 트러블슈팅 정리 (Readme.md 기준)

현재 문서는 루트 `Readme.md`의 **주요 기능** 및 **제가 기여한 부분(My Contribution)** 에 나온 기술 과제/해결 내용을 기준으로 정리했습니다.

## Backend

| 구분 | 기준 섹션 | 문제 | 해결 | 결과 |
| --- | --- | --- | --- | --- |
| 실시간 입찰 동시성 | 주요 기능 > 실시간 경매 시스템 | 동시 입찰 시 최고가 갱신 충돌 가능성 | `@database_sync_to_async` 기반으로 입찰 처리 로직을 비동기 안전하게 구성 | 동시 입찰 상황에서도 데이터 정합성 유지 |
| 결제 상태 관리 (ready/approval) | 기여 1. 카카오페이 결제 플로우 | 프론트 제약 환경에서 `tid`와 `payment_pk` 상태 연결이 어려움 | 사용자 식별자(휴대폰 번호) 키 기반 전역 딕셔너리로 상태 저장/연결 | 결제 준비-승인 단계 연동 안정화 |
| 미완료 결제 데이터 누적 | 기여 1. 카카오페이 결제 플로우 | 결제 미완료 건이 쌓여 데이터/리소스 비효율 발생 | 결제 시작 후 15분(테스트) / 2일(운영) 초과 시 자동 정리 로직 적용 | 불필요한 결제 데이터 누적 방지 |
| 검색 성능/유연성 | 기여 2. 검색 성능 최적화 | 단순 `LIKE` 검색은 대량 데이터에서 비효율, 필터 확장성 부족 | `django-filter` + `CharFilter` + `icontains` 기반 키워드/카테고리 필터링 | 검색 정확도와 유지보수성 향상 |
| 카테고리 모델 확장성 | 기여 2. 데이터 모델링 개선 | 다단계 카테고리 운영/조회가 비효율적 | `django-mptt` 트리 구조로 리팩터링 | 상/하위 카테고리 기반 조회와 관리 효율 개선 |
| 상품 삭제 무결성 | 기여 3. 상품 API 설계 | 임의 삭제 허용 시 데이터 무결성 훼손 가능 | JWT 인증 + “본인 상품” + “경매 진행 중 아님” 조건으로 삭제 제한 | 비즈니스 규칙을 API 레벨에서 강제 |
| 상품 이미지 처리 | 기여 3. 상품 API 설계 | 상품별 다중 이미지 처리 구조 부재 | `ProductImages` 모델과 관련 API/시리얼라이저 설계 | 다중 이미지 등록/조회 지원 |
